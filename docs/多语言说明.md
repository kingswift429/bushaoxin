# 多语言与多币种实现说明

## 支持范围

| 项目 | 值 |
|---|---|
| 源语言 | 简体中文（zh-Hans） |
| 上线语言 | 英语 en / 日语 ja / 韩语 ko |
| 资源格式 | `Localizable.xcstrings`（String Catalog，Xcode 15+） |
| 金额存储 | `Decimal` + ISO 4217 币种代码 |
| 汇率换算 | **不做**（见下方理由） |

---

## 一、文案架构

所有用户可见文案走三层：

```
视图层  Text(L.fieldGoods)
          ↓
L.swift  本地化键的集中注册表
          ↓
Localizable.xcstrings   zh-Hans / en / ja / ko 四份译文
```

### 为什么要有 `L.swift` 中间层

Xcode 的 String Catalog 靠代码字面量自动提取，但**动态拼接的场景它会漏**，
而且漏翻不会报错，只会掉回源语言 —— 上线后才发现就晚了。

把 key 写成常量后：调用点写错立刻编译失败，漏翻在 String Catalog 里显示为待翻译项。

### 带参数的文案必须显式用 `%lld` / `%@`

```swift
// ✅ 对：key 与 Catalog 完全对齐
String(format: String(localized: "card.voteCount %lld"), n)

// ❌ 错：插值会让 Xcode 推断出不同的占位符形式，查不到译文
String(localized: "card.voteCount \(n)")
```

这是最容易踩的坑：编译通过、不崩溃，但界面上直接显示 key 原文。

## 二、货币设计（三个关键决定）

### 1. 金额用 Decimal，不用 Double

账本要累加几百笔记录，Double 的二进制表示误差会累积成肉眼可见的偏差（10.1 + 20.2 ≠ 30.3）。

```swift
var price: Decimal          // ✅
var price: Double           // ❌ 累加会漂
```

### 2. 绝不跨币种相加

`MoneyBucket` 按币种分桶累加。把 ¥100 和 $100 合成 ¥200 是最常见也最尴尬的 bug。

```swift
var b = MoneyBucket()
b.add(Decimal(100), code: "CNY")
b.add(Decimal(100), code: "USD")
b.primary          // (CNY, 100) —— 主币种单独展示
b.sorted.count     // 2 —— 其余币种用小字并列，不合并
```

UI 上：主币种用大字号，其他币种一行小字排列（`¥100 + $100`）。

### 3. 不做汇率换算

理由：
- 汇率需要联网或内置离线汇率表，都会引入失败路径；
- 显示用户自己输入的数字才直观（香港用户看到 HK$58 才有感觉，看到 ¥53 反而要想一下）；
- 涉及汇率就要做合规声明，本期刻意避开。

**代价**：海外用户和在异地消费的用户，看到的"省下总额"是按币种分开的，不是单一数字。
这是诚实的设计取舍，不是缺陷。

## 三、货币格式化全自动

`NumberFormatter` 的 `.currency` 样式会自动处理各地区的麻烦事：

| 地区 | 输出 | 自动处理了什么 |
|---|---|---|
| 中国 | ¥15 | — |
| 美国 | $15.00 | 符号前置、两位小数 |
| 日本 | 15円 / ¥15 | **无小数位** |
| 韩国 | ₩15,000 | **无小数位**、千分位 |
| 德国 | 15,00 € | **符号后置**、小数点是逗号 |

不需要手写任何地区判断分支。

## 四、截图 OCR 的多地区适配

价格正则已覆盖主要写法：

```
¥15  ￥1,299.00   $12.99   €9,99   580円   1,200円   ₩6,800   12,000원
```

币种推断**顺序很重要**（`detectCurrency`）：

```swift
// 先匹配复合符号，再匹配单字符
("HK$", "HKD") → ("NT$", "TWD") → ("US$", "USD") ...
// 否则香港价格会被记成美元
```

同理 `¥` 在多地区共用，所以先判断 `元/円/원` 这些明确的后缀，再退到 `¥` → CNY。

## 五、模拟网友语料按语言分表

冷启动的"人气"全靠语料。如果海外用户看到的是中文审批理由，本地化会立刻穿帮。

`CrowdCorpus` 内置四套语料，`CrowdSimulator` 按系统语言取用。
理由的"口吻"也做了本地化，不是直译：

| 语言 | 驳回理由示例 |
|---|---|
| 中文 | 先冷静 24 小时，睡一觉大概就不想了。 |
| English | Sleep on it for 24 hours. You'll probably forget about it. |
| 日本語 | 24時間寝かせましょう。たぶん忘れます。 |
| 한국어 | 24시간 두고 보세요. 아마 잊을 거예요. |

种子广场内容同样是四套（商品和价格都按当地物价水平设定，日元 580、韩元 6800 而不是直接抄 15）。

## 六、新增一门语言要做什么

1. 打开 `Localizable.xcstrings` → 左下角 `+` → 添加语言；
2. 补齐所有 key（未翻译的会显示为待翻译，不会崩溃）；
3. `CrowdCorpus.swift` 加一套语料（否则该语言用户看到英文语料）；
4. `SeedData.swift` 加一套种子内容；
5. `project.yml` 的 `CFBundleLocalizations` 加上语言代码；
6. Xcode → 工程 → Info → Localizations 确认已勾选。

约 2~3 小时一门语言，工程量不大。**但语料和种子内容的质量决定成败**，
机翻会立刻让产品显得廉价。

## 七、App 名称的多语言

`app.name` 在四种语言下的取值：

| 语言 | 名称 | 说明 |
|---|---|---|
| 简体中文 | 不烧心 | 原梗直用 |
| English | Cool Head | "冷静一下"的意译，短好记 |
| 日本語 | ひと息 | "喘口气"，贴冲动消费前停顿的意象 |
| 한국어 | 한숨 | 双关："一口气"与"叹息" |

注意：**App Store 上的显示名由 App Store Connect 的元数据决定，不是这个 key**。
这个 key 只影响 App 内部标题。上架时要为每个地区单独填本地化名称。
