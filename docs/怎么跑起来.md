### 这个流水线已经帮我避开的坑

写这份 workflow 时请了一个 CI 专家做对抗审查，修掉了几个会导致
「你以为拿到错误了，其实什么都没拿到」的坑：

| 坑 | 后果 | 已修 |
|---|---|---|
| GitHub 用 `bash -e` 执行，`xcodebuild` 一失败就中止 | **错误汇总永远打印不出来**，只看到一个光秃秃的失败 | 加了 `set +e` |
| `grep ... \|\| echo` 在 pipefail 下误触发 | 编译明明失败，却打印「无 error」 | 改成 `if grep -q` 判定 |
| scheme 不存在时 `xcodebuild` 返回 0 | **假成功**，你会以为代码没问题 | 启动前硬校验 scheme |
| 退出码为 0 但没产出 `.app` | 空跑也报成功 | 校验 `.app` 产物存在 |
| `xcodegen` 失败后继续跑 | 报错变成「工程不存在」，方向全错 | 生成后立刻断言 `.pbxproj` |

这些都是「静默失败」类问题——不修的话，你会拿到一份看起来正常、
实际什么都没编译的日志。

### 免费额度够不够

| 仓库类型 | macOS 额度 | 折算 |
|---|---|---|
| 公共仓库 | 完全免费 | 随便跑 |
| 私有仓库 | 2000 分钟/月，macOS 按 **10 倍**计 | 约 200 分钟 ≈ 编译 20 次 |

对一个还没上线的 App，一个月 20 次编译完全够。

### 这条路线的限制

- ✅ 能验证：代码能不能编译、有哪些错误和警告、产物是否完整
- ❌ 不能验证：界面长什么样、点下去有没有反应、真机上的手感

界面必须靠第 2 层或第 3 层。

## 第 2 层：界面预览 —— 需要一台 Mac（哪怕是借的）

有 Mac 之后，只要 10 分钟：

```bash
brew install xcodegen
cd bushaoxin && xcodegen generate
open Bushaoxin.xcodeproj
```

然后按 `Cmd+R` 跑模拟器。

**没有 Mac 的替代方案**：
- 朋友/同事的 Mac 借 30 分钟，只做「编译 + 跑模拟器 + 截图」
- 闲鱼/淘宝租 Mac（云 Mac 约 ¥1~3/小时），足够跑一次验证
- 网吧/苹果体验店的 Mac 不行（装不了开发环境）

**这一步只需要做一次或两次**，不需要长期拥有设备。

## 第 3 层：真机 + TestFlight —— 上架前必须做

你已经有苹果开发者账号，所以这一步的钱已经花了，只缺 Mac。

用云端 macOS 也能完成（第 1 层的 workflow 加上 `xcodebuild archive` + `xcrun altool`/`notarytool` 上传），
但有两条路更省事：

1. **借 Mac 一次**，用 Xcode 的 Organizer 一键上传 TestFlight
2. **用云端 CI 上传**，需要把证书和 App Store Connect API Key 存进 GitHub Secrets

真机测试要验证的、模拟器验证不了的：
- OCR 拿真实购物截图识别（模拟器相册里没商品页）
- 通知真的会响
- StoreKit 沙盒购买流程
- 手感、动画流畅度

## 所以，"跑起来"到底该怎么做

**今天**（你有 Windows）：
```bash
node verify/logic-check.mjs        # 已完成，53 项通过
```

**下一步**（还是 Windows，10 分钟）：
把代码推到 GitHub → 点 Run workflow → 拿到编译错误 → 我修

**之后**（需要一次 Mac 接触，不用买）：
借/租 Mac 半天 → 编译跑模拟器 → 截图 → 修界面问题

**上架**：
Apple 后台填资料 + 上传 TestFlight

**结论：你不需要买 Mac 就能知道代码对不对。但你不能完全绕过 Mac 看到界面。**
最快路径是「云端编译拿报错」+「借一次 Mac 看界面」，成本约等于零。

## 附加：Swift 工具链（可选）

`verify/` 目录里还有一个 Swift Package，用于在 Windows 上验证 Swift 实现：

```bash
cd verify && swift run bushacheck
```

需要先装 Swift 工具链（`winget install Swift.Toolchain`，约 700 MB，
装完还要 Visual Studio Build Tools 提供链接器）。

**这一步是可选的**：Node 版已经验证了同一批逻辑。
它的价值在于确认「Swift 实现与逻辑一致」——比如 `Decimal` 的精度行为、
`NumberFormatter` 的本地化行为。如果装不上也不影响上架，跳过即可。
